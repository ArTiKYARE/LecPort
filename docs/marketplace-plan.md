# LecPort — Маркетплейс образования: архитектурный план

> Ниже — развёрнутое пояснение идеи и вариантов интеграции в текущий проект.
> Документ живой: обновляется по мере принятия решений.

---

## 1. Текущее состояние (что уже есть)

- Каталог учебных **материалов** (разделы: лекция / практика / лабораторная; предметы).
- Загрузка файлов (PDF/DOCX/PPTX) и карточек (JPG/PNG/GIF).
- Просмотр превью бесплатно, полный доступ — по покупке или подписке.
- Пользователи с ролями: admin / moderator / buyer.
- Кабинет, избранное, заметки на материалах.
- Организация данных: `catalog.json` (sections, subjects, materials, colors).

---

## 2. Видение

Превратить LecPort из «магазина одного продавца» в **двусторонний маркетплейс образования**:

- **кто-то создаёт** материалы, курсы, услуги, объявления;
- **кто-то покупает** оплаченный учебный контент и помощь;
- **кто-то помогает** другим за вознаграждение;
- площадка получает **комиссию** и дополнительный доход от продвижения и подписок.

Единая поисковая строка охватывает все сущности: материалы, курсы, услуги, объявления.

---

## 3. Ключевое понятие: «Организация»

Базовая единица **продавца**. Любой пользователь может создать организацию и от её имени вести продажи.

```
Organization {
  id, userId,
  name,
  description,
  avatar,
  rating, reviewCount,
  verified,          // «проверено площадкой»
  createdAt
}
```

Все продаваемые сущности привязываются к организации:

```
Material.organizationId?
Course.organizationId
Service.organizationId
Bounty.organizationId?
```

## 4. Модули

### 4.1. «Маркет» — материалы и курсы

| Аспект | Описание |
|---|---|
| Что это | Пользователь создаёт организацию и выставляет материалы / курсы на продажу. Существующий каталог масштабируется до маркетплейса. |
| Цены | Материалы: 49 / 99 / 149 / 299 ₽. Курсы: фиксированная цена или по разделам/модулям. |
| Комиссия | **15%** с каждой продажи (автоматически). |
| Поиск | Единый запрос ищет по названию, описанию, тегам, имени организации. |
| Данные | `Material.price`, `Material.organizationId`; новая сущность `Course` (title, description, sections = упорядоченные списки материалов, price, organizationId). |

**Плюсы:** понятная и апробированная модель (Udemy, Skillbox), низкий порог входа для продавца.
**Минусы:** ценовая конкуренция с бесплатными материалами; нужны модерация и контроль качества.

---

### 4.2. «Помощь» — услуги (репетиторство, работы на заказ)

| Аспект | Описание |
|---|---|
| Что это | Объявление об услуге: репетиторство, выполнение лаб / контрольных / дипломных, написание кода, разбор тем. |
| Рейтинг | Звёзды 1–5 + текстовые отзывы. Отзывы привязываются только к подтверждённым сделкам. |
| Комиссия | **15%** с каждой оплаченной услуги. |
| Данные | `Service` (title, description, priceType: fixed/hourly, price, category, organizationId, rating, reviewCount); `Review` (targetType/targetId, authorId, rating, text, createdAt). |

**Плюсы:** высокая маржинальность (услуги стоят дороже материалов), возвратные клиенты.
**Минусы:** качество сложнее проверять; нужен понятный порядок споров.

---

### 4.3. «Биржа» — одноразовые запросы (bounty)

| Аспект | Описание |
|---|---|
| Что это | Заказчик публикует задачу с вознаграждением: «Помогите объяснить теорию вероятностей, 300 ₽». |
| Механика | Заказчик оплачивает (эскроу) → помощники откликаются → заказчик выбирает лучший ответ → деньги переводятся. |
| Комиссия | **15%** с исполнителя. |
| Данные | `Bounty` (title, description, reward, subjectId, deadline, status: open/in_progress/resolved/cancelled, authorId); `BountyResponse` (bountyId, helperId, text, status). |

> Отличие от «Помощи»: услуга — это «я всегда этим занимаюсь, наймите меня»;
> биржа — это «мне прямо сейчас нужна разовая помощь, вот вознаграждение».

**Плюсы:** геймификация, вовлечение, привлекает новую аудиторию «помощников».
**Минусы:** самый сложный модуль (эскроу, споры, модерация, мошенничество). Запускать позже всех.

---

### 4.4. «Продвижение» — платная реклама объявлений

| Аспект | Описание |
|---|---|
| Что это | Платное продвижение карточки: «неделя в топе», выделенный бейдж, приоритет в поиске. |
| Тарифы | Неделя в топе — 179 ₽; месяц — 499 ₽ (предложение обсудить). |
| Данные | Поля `promotedUntil: Date`, `priority: number` в Material / Service / Bounty. Сортировка: сначала promoted, затем рейтинг/дата. |

**Плюсы:** простой и быстрый доход без комиссии; несложная реализация.
**Минусы:** риск злоупотребления — нужен лимит на продвижение одного объявления.

---

### 4.5. «Внутренняя валюта» — коины

| Аспект | Описание |
|---|---|
| Что это | Покупка коинов пакетами; оплата коинами внутри платформы; вывод 1:1 (или по настроенному курсу). |
| Пакеты (пример) | 100 коинов = 99 ₽ · 500 = 475 ₽ (−5%) · 1000 = 900 ₽ (−10%) · 5000 = 4250 ₽ (−15%). |
| Зачем | Удобные микроплатежи (49 ₽ = 50 коинов), «заморозка» денег пользователя (LTV↑), меньше friction при покупке. |
| Данные | `CoinBalance`, `CoinTransaction`, `CoinPackage`. |

**⚠️ Юридический риск:** деньги → коины → платежи (и вывод) — это квазиэлектронные деньги.
Требуется консультация юриста/агрегатора (например, работа через ЮKassa с эквайрингом и выводом).
**Вывод:** модуль откладываем до достаточной транзакционной базы и юридической проверки.

---

### 4.6. «Премиум» — подписка

| Аспект | Описание |
|---|---|
| Что это | Ежемесячная подписка (например, 299 ₽/мес) с привилегиями. |
| Привилегии (пример) | Доступ к материалам без отдельных покупок, приоритет в поиске, сниженная комиссия для продавцов (10% вместо 15%), бейдж «Премиум», ранний доступ к курсам. |
| Данные | Поле `User.premiumUntil: Date` + проверка доступа. |

**Плюсы:** предсказуемый recurring-доход.
**Минусы:** конкурирует с продажей отдельных материалов; необходимо оправдать ценность подписки.

---

### 4.7. Прочие идеи ассистента

| Идея | Оценка |
|---|---|
| Продажа пакетов по конкретным дисциплинам | **Отложить.** Плохо масштабируется и запутывает предложение — дисциплины уже закрываются предметами + разделами. |
| Реклама организаций | **На будущее.** Логичное продолжение модуля «Продвижение», запускать после появления базы организаций. |

## 5. Рекомендуемая очерёдность

| Приоритет | Модуль | Почему |
|---|---|---|
| **P0** | Организации + Маркет (материалы с ценами) | Ядро платформы — без него ничего не работает. Организация = базовая единица продавца. |
| **P1** | Курсы | Увеличивают средний чек, повышают вовлечение. |
| **P1** | Продвижение | Простая реализация + прямой доход почти сразу. |
| **P2** | Помощь (услуги + рейтинги + отзывы) | Вторая половина маркетплейса; высокая маржа. |
| **P2** | Премиум | Recurring-доход, но нужна критическая масса контента. |
| **P3** | Внутренняя валюта | Только после юридической экспертизы и роста транзакций. |
| **P3** | Биржа | Самый сложный (эскроу, споры); запускать последним. |

### Почему именно такое начало

1. **Организации** — без них платформа не масштабируется: сейчас контент создаёт один админ, а организации превращают каждого пользователя в продавца.
2. **Маркет** — это почти готово (каталог + загрузка + оплата). Нужно лишь добавить `organizationId` и `price` в материал + страницу организации.
3. **Курсы** — естественное развитие: «связка материалов с обложкой» превращается в структурированный продукт, средний чек растёт в разы.
4. **Продвижение** — пара дней разработки и немедленный доход (лучший ROI).

Остальное подключается по мере роста базы пользователей и юридической готовности.

## 6. Технические изменения (сводно)

| Сущность | Куда добавляется |
|---|---|
| `Organization` | Новая модель и CRUD; связь `userId → organization`. |
| `Material.price`, `Material.organizationId` | Расширение модели материала; отображение цены в карточке. |
| `Course` | Новая модель: title, description, price, sections (списки материалов), organizationId. |
| `Service` | Новая модель объявления об услуге + категории. |
| `Review` | Новая модель отзывов и рейтингов (к материалу/курсу/услуге). |
| `Bounty`, `BountyResponse` | Новые модели биржи. |
| Продвижение | Поля `promotedUntil`, `priority` в продаваемых сущностях. |
| `User.premiumUntil` | Поле и проверка доступа. |
| Коины | `CoinBalance`, `CoinTransaction`, `CoinPackage` (после юр. проверки). |
| Поиск | Единый `API: GET /api/search?q=&type=&subject=&minPrice=&maxPrice=&sort=` по всем сущностям. |

## 7. Открытые вопросы к решению

1. **Эскроу по услугам и бирже:** платить продавцу сразу или после подтверждения заказчика (удержание 15% + потенциальный возврат)?
2. **Проверка организаций:** автоматическая регистрация всех или ручная модерация (badge «проверено»)?
3. **Тарифы продвижения и премиума:** финальные цифры и скидки для первых клиентов.
4. **Юридика валюты:** выбираем агрегатор/решение до реализации коинов.
5. **Частные случаи отказа:** что считается «выполненным заказом» и как решаются споры.
